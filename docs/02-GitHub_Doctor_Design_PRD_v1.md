## 1. 제품 개요

### 1-1. 브랜드 & 슬로건

| 항목 | 내용 |
|---|---|
| 브랜드명 | GitHub Doctor |
| 슬로건 | "진단하고, 고치고, Push한다 — 자동으로." |
| 핵심 철학 | 사용자는 코드에만 집중한다. 인증·계정·환경 문제는 GitHub Doctor가 책임진다. |

### 1-2. 한 줄 제품 정의

> macOS와 Windows에서 동작하는 Electron + AI 기반 크로스 플랫폼 앱으로, GitHub 인증·계정 문제를 자동 진단하고 — Keychain 정리, Git 설정 교체, PAT 재인증, origin 재연결까지 — 사용자 개입을 최소화한 완전 자동 복구로 Push 성공을 보장한다.

### 1-3. 제품 목표

- 초보자도 GitHub 인증·계정 문제를 스스로 해결할 수 있게 한다
- 문제 발생부터 Push 성공까지 소요 시간을 10분 → 1분으로 단축한다
- 수동 터미널 작업 없이 AI가 원인을 특정하고 자동으로 복구한다
- macOS / Windows 양 플랫폼에서 동일한 UX를 제공한다

## 2. 배경 및 문제 정의

### 2-1. 문제 배경

하나의 디바이스에서 여러 GitHub 계정을 사용하는 환경이 일반화되면서, 인증 주체가 여러 레이어로 분산되어 충돌하는 현상이 빈번하게 발생한다. 이 문제는 초보자에게 특히 치명적이며 해결 경로를 파악하기 어렵다.

### 2-2. 발생 가능한 변수 전체 목록

#### 🔴 인증 레이어 충돌 (가장 빈번)

| 변수 | 설명 | OS |
|---|---|---|
| Keychain 오염 | 이전 계정 PAT가 키체인에 잔존, 오계정으로 자동 인증 | macOS |
| Windows Credential Manager 충돌 | `git:https://github.com` 키가 단일 계정만 저장 — 다중 계정 불가 | Windows |
| GCM 미설정 | credential helper 누락 또는 혼용 | Both |
| PAT 만료 | Personal Access Token 유효기간 초과 | Both |
| PAT 권한 부족 | repo scope 미포함 토큰으로 push 시도 | Both |
| SSH 키 미등록 | GitHub 계정에 공개키가 등록되지 않음 | Both |
| SSH 키 충돌 | 여러 계정에 동일 SSH 키 사용 (1:1 원칙 위반) | Both |
| SSH agent 미실행 | ssh-agent 꺼진 상태로 인증 시도 | Both |
| DSA 키 사용 | 2022년 3월 이후 GitHub 완전 폐기 형식 | Both |
| 1년 미사용 SSH 키 자동 삭제 | GitHub 보안 정책으로 비활성 키 자동 제거 | Both |

#### 🟡 계정 레이어 충돌

| 변수 | 설명 | OS |
|---|---|---|
| user.name / email 불일치 | 커밋 작성자 정보가 현재 저장소 계정과 다름 | Both |
| global vs local 설정 충돌 | global 설정이 local을 덮어쓰거나 반대 상황 | Both |
| 다중 계정 namespace 미분리 | HTTPS 다중 계정 사용 시 충돌 | Windows |
| Collaborator 미등록 | push 계정이 소유자도, Collaborator도 아닌 상태 | Both |
| Organization SSO 미완료 | Org 저장소 SSO 인증 미완료 상태 | Both |

#### 🟠 Remote 레이어 충돌

| 변수 | 설명 | OS |
|---|---|---|
| origin 주소 오류 | HTTPS/SSH 주소 혼용, 오탈자 | Both |
| origin already exists | 이미 등록된 remote 중복 추가 시도 | Both |
| HTTPS ↔ SSH 프로토콜 혼용 | 인증 방식과 URL 프로토콜 불일치 | Both |
| 방화벽 / 프록시 차단 | 22번 포트 차단 환경, HTTPS fallback 필요 | Both |
| CA 루트 인증서 만료 | OS 인증서 갱신 누락으로 TLS 연결 실패 | Both |

#### 🟢 배포 연동 레이어 충돌

| 변수 | 설명 | OS |
|---|---|---|
| Firebase 계정 불일치 | GitHub 계정과 Firebase 연동 계정이 다름 | Both |
| GitHub Actions 토큰 만료 | CI/CD 자동화에 사용된 토큰 만료 | Both |
| 배포 서비스 OAuth 만료 | Vercel, Netlify 등 GitHub 앱 권한 만료 | Both |

## 4. 핵심 기능 정의

### Phase 1 — 자동 스캔

앱 실행 즉시, 선택한 프로젝트 폴더 기준으로 아래 항목을 자동 수집한다.

| 스캔 항목 | macOS | Windows | 비고 |
|---|:---:|:---:|---|
| Git 설치 여부 및 버전 | ✅ | ✅ | |
| user.name / user.email (global/local) | ✅ | ✅ | local 우선 적용 |
| credential helper 종류 | ✅ | ✅ | osxkeychain / manager / wincred |
| Keychain GitHub 인증정보 | ✅ | — | security CLI 사용 |
| Windows Credential Manager 항목 | — | ✅ | cmdkey 명령 사용 |
| SSH 키 존재 여부 및 유형 | ✅ | ✅ | DSA 감지 포함 |
| ssh-agent 실행 상태 | ✅ | ✅ | |
| origin remote 주소 및 프로토콜 | ✅ | ✅ | HTTPS / SSH 구분 |
| GitHub API 연결 상태 | ✅ | ✅ | 네트워크·방화벽 감지 |
| PAT 유효성 및 만료일 | ✅ | ✅ | GitHub API 호출 검증 |
| SSH 키 GitHub 등록 여부 | ✅ | ✅ | GitHub API 확인 |

### Phase 2 — AI 진단

- 스캔 결과 전체를 Claude AI에 전달
- 충돌 원인 우선순위 정렬: Critical / Warning / Info 3단계
- 최적 복구 경로 1개 결정 + 대안 경로 제시
- 초보자용 자연어 설명 및 단계별 안내 생성

### Phase 3 — 자동 복구

| 복구 항목 | 자동 | 반자동(1클릭) | 안내만 |

| origin remote 주소 수정 | ✅ | | |
| credential helper 설정 | ✅ | | |
| SSH 키 생성 (Ed25519) | | ✅ | |
| SSH 공개키 클립보드 복사 + 등록 안내 | | ✅ | |
| PAT 재발급 (GitHub 설정 페이지 오픈) | | | ✅ |

## 6. 기술 스택 & 아키텍처

### 6-1. 기술 스택

| 레이어 | 기술 | 역할 |
|---|---|---|
| UI 프레임워크 | Electron + Vue 3 / React | 크로스 플랫폼 데스크탑 앱 |
| AI 엔진 | Claude API (`claude-sonnet-5`) | 진단 분석 및 자연어 안내 |
| 진단 엔진 | Node.js + child_process | Git CLI 실행, SSH 검사, 인증 분석 |
| macOS 인증 | security CLI (Keychain) | Keychain 항목 조회·삭제 |
| Windows 인증 | cmdkey + PowerShell | Credential Manager 조작 |
| 패키지·배포 | electron-builder | .dmg / .exe 인스톨러 생성 |
| 보안 저장소 | keytar (Node.js) | OS 네이티브 보안 저장소 연동 |
| 자동 업데이트 | electron-updater | 버전 자동 업데이트 |

> ⚠️ **모델 ID 주의**: Claude API `model` 파라미터는 시점에 따라 최신 버전이 바뀝니다. 구현 착수 시 Anthropic 공식 문서/콘솔에서 현재 유효한 모델 ID를 재확인하세요. 본 문서 기준 권장값은 `claude-sonnet-5`입니다.

## 7. 자동화 범위 & 처리 기준

### 7-1. 자동화 3단계 기준

| 단계 | 기준 | 예시 |
|---|---|---|
| 완전 자동 | 사용자 확인 없이 즉시 실행 가능한 안전한 작업 | Keychain 삭제, user.name 교체, origin 수정 |
| 반자동 (1클릭) | 사용자 확인이 필요하나 앱이 실행 주체인 작업 | SSH 키 생성, 공개키 GitHub 등록 |
| 안내만 | 외부 서비스 접근 또는 보안상 앱이 대신 불가한 작업 | PAT 재발급, Firebase 재연동 |

### 7-2. 복구 실행 흐름

```
앱 실행
  ↓
[Step 1] 프로젝트 폴더 선택 (드래그&드롭 / 탐색기)
  ↓
[Step 2] 자동 스캔 (10초 이내, 진행 바 표시)
  ↓
[Step 3] AI 진단 결과 표시 — 원인 우선순위 정렬
  ↓
[Step 4] "자동 복구 시작" 버튼 1회 클릭
  ↓
[Step 5] 단계별 복구 진행 (진행 상황 실시간 표시)
  ↓
[Step 6] Push 성공 확인 화면 — ✅ 완료
```
